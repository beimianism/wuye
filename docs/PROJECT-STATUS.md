更新日期：2026 年 10 月 21 日。运行状态核对时间：北京时间 12:18 左右。

本文面向项目负责人和后续开发、部署人员，记录当前交付范围、代码状态、已验证能力及后续工作。文中的“已保留”表示代码未被裁剪；“已验证”仅指明确列出的测试或查询场景，不代表所有业务流程均已验收。

## 1. 当前结论

项目已完成原始版本的 Git 留档、第一轮功能裁剪、管理后台与 Java 后端的本地启动验证，并上传至 GitHub 私有仓库。当前是可继续开发的裁剪版本，尚未完成面向客户的正式部署、移动端运行和公众号支付闭环。

目前采用菜单移除、页面注册移除、接口拦截及任务停用的方式裁剪功能，**没有彻底删除被裁剪模块的全部源码和数据库表**。保留功能的部分查询已通过真实浏览器验证，其他增删改及完整业务流程仍需逐项验证。

本次状态核对发现：本地 MySQL 的 13306 端口未监听；Web、Java 服务和其他中间件的已记录端口仍在监听。因此，不能将当前运行状态描述为“所有业务均可使用”。数据库停止原因未在本次文档整理中排查。

原始页面文件、共享 Java 类型和历史数据库表大部分仍在仓库中，目的是保留跨模块引用和版本追溯能力。后续如需交付不含停用源码的版本，还需另做源码删除、依赖清理及完整回归。

## 5. 本地运行与数据库

### 5.1 已完成的本地环境工作

项目使用独立的 Java 8、Maven、Redis、Kafka 和 ZooKeeper 工具及运行目录，不修改系统默认 Java 21。MySQL 使用项目内独立数据目录 `.runtime/mysql/data`，未复用电脑原有的 `D:\MySQLData` 数据。

附带的 0.6 商业版 SQL 已导入两个数据库，共 384 张表。源码为 0.8，已经针对登录、小区查询、房屋查询和全部缴费记录查询补齐部分缺失字段及路由元数据。迁移支持重复执行；已标记导入的数据库不会被重新导入覆盖。

附带数据没有房屋、业主、费用及缴费明细，默认小区相关页面为空。后续需要录入或导入客户的基础资料和收费规则，再验证实际出账及收款场景。

### 5.3 常用命令

在项目根目录的 PowerShell 执行：

```powershell
# 启动或恢复本地中间件，然后启动服务
python scripts/local.py infra
python scripts/local.py start all
python scripts/local.py status

# 停止本项目记录的进程
python scripts/local.py stop
```

恢复数据库后，应重新验证管理后台登录及业主、房屋、费用查询；如服务未恢复数据库连接，再按日志定位或重启对应服务。

首次迁移至另一台电脑，需要额外准备工具、安装 Web 依赖、导入 SQL 和构建 Java。GitHub 不包含 `.tools`、`.runtime`、`node_modules` 及构建输出；仅克隆仓库不能直接获得当前电脑的完整运行环境。详细步骤见 [本地开发说明](LOCAL-DEVELOPMENT.md)。

本地启动器默认暂停全部定时任务，所以当前配置不会自动出账或自动发送费用提醒。收费规则、账单生成及通知相关代码仍保留。

启用保留任务前，应完成本地任务、费用和微信配置，并检查导入的历史任务。报修、设备、巡检等已裁剪任务仍受停用规则限制。

## 6. 账单和支付流程现状

客户的核心目标是：**后台生成账单 → 公众号推送 → 业主确认账单详情并在线支付 → 后台自动同步支付信息**。财务核对、发布等环节应在后续实现时落实具体操作和状态规则。

### 6.1 可以复用的现有逻辑

后端已有 `GenerateBillTemplate`、`GenerateBillProTemplate` 等账单任务。其主要逻辑为：按小区和出账类型读取收费项目；检查对应期间是否已经出账；读取关联费用；按收费配置和计算服务计算应收、欠费等信息；生成账单及相关明细。没有关联费用时不生成该项目账单。

这些代码可以作为后续计费与出账的基础，仍需结合客户收费规则验证周期、面积或单价、欠费计算、重复执行及异常处理。本轮未使用真实客户数据跑通出账，也未完成财务核对发布流程。

公众号费用通知任务和微信支付回调代码同样存在。回调实现包含签名校验、重复处理判断以及调用费用入账接口的逻辑，但这是既有代码能力，尚未完成当前项目的真实支付验证。上线前仍需核对适用的微信支付产品、接口版本和商户配置。

### 7.1 已确认的外部条件

- 公众号为刚注册的服务号，**尚未完成微信认证**。
- 微信支付尚未开通，没有已配置并验证的支付商户号。

- 当前管理后台仅完成本地运行验证，未在上述服务器部署验收。
- 本项目尚未录入并验证客户的 AppID、AppSecret、回调地址、授权域名和通知模板。

### 7.2 可采用的测试方式

微信官方提供 [公众号接口测试号](https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login)。可以先申请独立测试号，让测试人员关注，并在测试号实际开放权限范围内验证服务器接入、微信授权、业主绑定、账单页面及消息通知。

测试号尚未在本项目配置或联调。测试号与正式服务号是不同账号，不能把测试号上的关注关系和 OpenID 直接当作正式服务号的用户身份。测试号也不能代替支付商户号完成真实收款验证。

微信服务器回调需要公网可访问地址，`127.0.0.1` 不能用于微信远程回调。开发时可评估临时公网映射；正式环境应根据服务器地域和微信平台实际要求准备域名、HTTPS、授权域名、IP 白名单等配置。正式服务号的授权和通知能力，应在认证及对应接口权限确认后验收。

### 7.3 已发现的接入障碍

旧公众号配置表单强制填写支付商户号、支付参数，保存接口也包含支付密钥非空校验。若先接入公众号、以后再开通支付，需要调整相关校验与支付入口，明确未开通支付时的展示和处理方式；本轮尚未实施该调整。

业主网页尚未构建和运行，因此当前不能直接在公众号菜单中提供已经验证可用的手机端账单入口。

## 9. 建议的后续工作顺序

1. **恢复开发环境。** 恢复独立 MySQL，检查日志并复验登录和核心查询；整理服务器地域、配置及部署条件。
2. **准备基础业务数据。** 录入测试小区、楼栋、房屋、业主和收费项目，明确客户的收费规则与出账周期。
3. **运行业主端。** 准备 HBuilderX 和 H5 构建，验证本地及手机访问、身份与房屋绑定、账单查询。
4. **接入公众号测试号。** 先支持无支付商户号的公众号配置，完成公网回调及授权、身份绑定和通知的联调。
5. **完成账单业务。** 验证复用计费逻辑，落实财务核对、发布、业主账单详情及确认状态，验证重新执行和异常恢复。
6. **切换正式服务号。** 完成认证、域名及权限配置后，用正式号重新验证身份关系、菜单和通知。
7. **接入微信支付。** 开通商户号，完成下单、签名和金额校验、异步通知、重复通知处理、后台同步及对账，再验收真实资金流程。

以上是建议顺序，不是已完成事项，也不构成工期或成本承诺。
