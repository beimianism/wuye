# 公众号测试号与本地系统联调设计

用户已于 2026-10-21 确认采用本地后端、公众号测试号和临时公网入口，暂不部署整套系统到杭州 2 核 2 GB 服务器，也不开发小程序或真实支付。本文落实这一已确认方案，不重复增加审批环节。

## 本轮目标

恢复独立数据库和本地管理后台；让现有业主 uni-app 的 H5 版本可重复构建、运行；允许在未开通微信支付时配置公众号；提供只转发业主业务和微信接入路径的公网入口；用测试号验证真实微信身份和绑定、账单查询的可用性。测试号密钥只存放在忽略的本地配置，禁止出现在日志、Git 或浏览器响应中。

沿用现有 H5 比新写整套业主页面更便于保留收费逻辑；沿用本地后端比迁移到 2 GB 服务器更符合现有资源。构建优先补充命令行工具链，不要求用户安装微信开发者工具。若原 H5 存在平台专用 API，针对保留的登录、绑定、我的房屋及账单路径修复。

## 接入结构

微信测试号 / 手机 → 临时 HTTPS 域名 → 本机专用联调入口 → 业主 H5 与 front 服务 → 本地业务服务和独立 MySQL。

管理后台、服务发现、数据库、配置密钥及内部服务端口不通过该入口开放。微信服务器校验与授权回调按平台要求公开，其他业务依赖现有登录和必要的测试访问限制。公众号菜单只有明确的业主页面，发布或发送通知前必须使用已确认的测试号和测试对象。

## 验证与交付边界

本地验证覆盖 H5 实际构建及浏览器打开、无支付配置保存和更新、OAuth 回调及重定向、入口路径限制和凭据不泄露。微信端验证需要用户扫码并在测试号平台保存回调、授权域名及关注测试号；平台操作不能用本地模拟冒充完成。

未配置真实商户号时禁止真实下单，页面明确提示未开通。原账单自动任务仍默认暂停；不将空数据查询或模拟支付描述为实际出账、收款。通知准备可以做，实际发送仅针对用户明确指定的测试对象。

公网临时域名可能变化，提供更新配置和重启方法。工具、依赖及运行时秘密保持在 Git 忽略目录；源码、测试、示例配置和操作说明入库。
