# 单条账单公众号推送

用户已确认需要在现有后台增加“选中一条账单，点击发送”的入口。本次在当前功能分支和本机环境实现，不创建新的运行目录。

在账单管理的欠费清单逐行增加推送按钮，未支付可推送，已通知可明确确认后再次推送，已支付不可推送。确认信息包含业主、房屋和金额。完成后刷新当前列表；错误直接展示，不将接口受理描述为业主已经收到。修正已有催缴状态筛选的代码值。

方案比较：直接启动现有定时任务会遍历全部小区，不适合单条操作；浏览器直接调用微信会泄漏密钥；采用受登录保护的单条后台 API，仅接受小区、欠费明细 ID 和请求 ID。复用公众号配置、模板协议和费用服务，按账单实际 ownerId 筛选审核通过的 WECHAT 绑定，去重 OpenID，前端不得指定收件人或金额。后台再次校验物业和小区关系、当前账单及未支付状态。

发送使用当前公众号及其欠费通知模板，房屋链接使用现有费用列表并定位房屋。Redis 保存单次请求结果和每个收件人的受理记录，锁定同一明细防止并发，发送成功后短时限制再次发送。微信明确拒绝不更新账单；超时和部分成功返回明确结果，不能自动重试已受理收件人。成功状态仅表示微信受理，支付状态不改变。

不增加批量发送，不开启全局定时任务，不进行真实支付，不代替用户点击真实发送。测试使用替身验证发送路径；真实后台浏览器核验按钮、确认和无效请求，真实推送由用户操作。免费隧道到期时需要重建并更新网页授权域名。
